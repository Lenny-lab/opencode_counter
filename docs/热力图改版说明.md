### 现状缺陷（对照用户提供的截图 1-4）

| # | 缺陷 | 位置 |
|---|------|------|
| 1 | 网格在卡片内**居中悬浮**，左右大量留白，短区间（7天）只有 1 列巨大方格（40pt）悬在中间，观感像坏掉 | `calendarGrid` 的 `Spacer` 居中逻辑 |
| 2 | 空白日期格只有**描边**、填充色几乎不可见（`D.cellEmpty` = `0x0B0D13` @55%，与背景 `0x04060D` 几乎同色），整张图看起来像散落的孤岛 | `calendarCell` |
| 3 | 月份标签在网格**顶部**且**会重叠**（截图中出现「06月07月」「03月4月」挤在一起） | `monthLabel` + 顶部 HStack |
| 4 | 左侧周几标签（周一/周三/周五/周日）占宽 34pt，与 ChatGPT 设计不符（ChatGPT 无周几标签） | `calendarGrid` labelW |
| 5 | 格子尺寸按周数分档硬编码（40/30/22/16/13/11），短区间格子过大、长区间过小，且不随卡片实际宽度自适应 | `calendarGrid` size 分档 |

### 参考设计要点（ChatGPT「Token 活动」，截图 5）

- 7 行（星期）× N 列（周），**横向铺满整个内容宽度**，无左右留白。
- 方格小而均匀，圆角小（约 2-3pt），间距 3-4pt。
- **无周几标签**（或最多在最左列极简标注，可直接去掉）。
- 月份标签在网格**下方**，只在月份变化处标注一个，间距不足则跳过，绝不重叠。
- 空日期格是**可见的浅灰实心块**（GitHub contribution graph 风格），不是透明+描边。
- 有数据格为蓝色系深浅分级，颜色越深值越大。

## 2. 硬性验收标准

1. **每格 = 一整天**。禁止按小时/2小时分块渲染（网页版 `heatmap-chart.tsx`
   的 7/30/90 天 `hourly` 模式是**有意偏离项**，不要向它对齐）。
2. 格子尺寸随卡片可用宽度自适应：`size = (可用宽 - gaps) / 周数`，clamp 到
   **[8, 20]pt**，gap 固定 3pt；网格**左对齐**（不要居中悬浮）。
   当 `周数 × (size+gap) < 可用宽` 时，可用 `Spacer` 把网格顶到左侧贴边即可。
3. 删除周几标签列（`labelW` 直接去掉或置 0）。
4. 月份标签移到网格**下方**一行；规则：某周的第一天跨入新月份才标注，
   且与上一个已显示标签的水平距离 < 24pt 时**跳过**（防重叠）。
5. 空格子：实心浅色填充（建议 `Color.white.opacity(0.06)` 或与现调色板协调的
   深灰），**保留极淡描边或无描边均可，但填充必须肉眼可见**。
6. 数据格：保留现有分级算法 `HeatmapCard.level()`（sqrt 归一）与
   `LEVEL_PCT = [0,22,42,62,82,100]`，主色 `D.primary = 0x6492FF`。
7. 保留交互：hover tooltip（日期 + 当日总量）、底部图例「少→多」、右下角合计。
8. 不改数据口径：数据来自 `UsageSeries.days`（按天零填充聚合），
   今日按本地午零点清零（`OpenCodeDatabase.swift` 今日 SQL 口径勿动）。

## 4. 构建 / 验证 / 装机

### 4.1 无头渲染 harness（改完先快速看图）

harness 位于临时目录（重启可能被清理，**丢了就按下述方法重建**）：

```

├── stub.swift      # Formatters 等最小 stub（让 DashboardView 能脱离 Xcode 编译）
├── main.swift      # 入口：./dashrender <mode>，渲染 PNG 到 /tmp/heat_*.png
└── patched/DashboardView_noscroll.swift  # sed 产物，见下
```

重建/编译（**不要** 编入 `Helpers.swift`，会与 stub 冲突）：

```bash
SRC="/Users/putou/Desktop/opencode个人使用量检测/vendor/opencode-stats-main/OpenCode Stats"
H="/var/folders/1l/mv4z4xns5xs484yk0ljrkn5c0000gn/T/opencode/dashrender"
mkdir -p "$H/patched"
# ImageRenderer 无法渲染 ScrollView：把最外层 return ScrollView { 换成 Group {
sed 's/return ScrollView {/return Group {/' "$SRC/DashboardView.swift" > "$H/patched/DashboardView_noscroll.swift"
xcrun swiftc -o "$H/dashrender" "$H/stub.swift" "$H/main.swift" \
  "$H/patched/DashboardView_noscroll.swift" \
  "$SRC/OpenCodeDatabase.swift" "$SRC/ExportSheet.swift" "$SRC/CSVExporter.swift"
```

> 若 `stub.swift` / `main.swift` 已丢失：stub 需提供 `enum Formatters`
> （`full(Int64)/full(Double)/compact/axis/monthDay/yearMonthDay/monthDayTime/utcOffset`
> 全套静态方法，完整清单以 `grep -n "Formatters\." DashboardView.swift` 的
> 调用点为准）；main 需支持
> `7 / 30 / all / hover7 / hoverall` 几个 mode，用 `ImageRenderer` 出 PNG。
> 丢失时最稳妥的做法是重建一个只渲染 `HeatmapCard` 的最小 main。

渲染并肉眼检查（正常路径，不必 OCR）：


**验收看点**：① 无顶部月份重叠标签；② 无周几标签；③ 空格子可见；
